# M-F assessment contract proof

Status: non-production executable checkpoint evidence. These fixtures specify
the approved producer-to-M-F boundary; they do not authorize ranking, UI,
orchestration, provider linking, or side effects.

The proof starts with an exact M-E candidate and compatibility receipt, one
ready M-D hardware target, an explicitly attributed host-only or two-pool
allocation profile and attributed capacity policy produced by the M-F
admission functions, real M-G evidence component shapes, and optional M-B
state. It verifies:

- exact candidate/artifact/runtime/hardware/context bindings;
- independent device and host arithmetic down to every byte component;
- visible `does-not-fit`, `partial`, `unavailable`, `blocked`, and `error`
  outcomes;
- unchanged absence of performance evidence and M-B advice;
- rejection of unsupported, wrong-channel or mismatched evidence and unbound
  upstream advice;
- deliberate non-use of `tight` until its semantics are owner-approved;
- no recommendation roles, ranking, response-quality claim, UI dependency,
  network, process, or storage behavior.

Run from the repository root:

```powershell
npm.cmd run proof:mf
```
