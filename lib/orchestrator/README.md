# M-O application orchestration

This package is the application boundary between surfaces and the approved
domain modules. The current checkpoint implements the smallest first-slice
vertical seam:

1. validate matching M-A hardware and recommendation-request envelopes;
2. obtain a complete candidate universe through an injected port;
3. clone plain DTOs, apply the process-local M-E/M-F composition brand, and call
   M-H;
4. retain the frozen universe for an exact-configuration detail lookup;
5. create a canonical, 24-hour M-A runner handoff with no model data and no
   side-effect authorization;
6. package that unchanged handoff with its exact M-E receipt in the separately
   hashed U28 bundle and inspect it under U29 expiry semantics;
7. compose U30 context decisions, preview permissions, preserve M-I inventory
   states and admit only intact verified artifact identity;
8. validate a non-authorizing verification-plan preview against intact
   upstream state.

Port failures retain `unavailable`, `blocked`, or `error`; M-O never promotes
them to data. The package contains no registry, fit, evidence, ranking, UI,
network, filesystem or process algorithm.

The exact TypeScript-to-Rust M-J preparation adapter still must represent
confirmed hardware, observed tool identity, preflight and benchmark/quick-check
settings without defaults. Verification run/progress/stop/result and actual
surface wiring remain unfinished. U27 also means the real candidate-universe
provider must currently return an honest unavailable result rather than
synthetic production recommendations.
