## How agents use these files

1. Read `../PRODUCT-BRIEF.md` and `../unresolved-decisions.md` first.
2. Treat a prototype interaction as a question or candidate pattern, not a
   requirement.
3. Map candidate behavior to a named W/D/C screen state and proposed M-O use
   case; do not treat that mapping as approved while `screen-contract.md` is in
   review.
4. Replace all illustrative values with typed fixtures in tests; never import
   prototype data into production.
5. Preserve familiar chat/search/CLI patterns while applying the repository's
   Forest tokens and honesty rules.

The candidate consolidated review matrix is `../screen-contract.md`.
`../interface-design-program.md` and `../ui-reference-and-screen-plan.md` are
preserved research, not current screen authority.
